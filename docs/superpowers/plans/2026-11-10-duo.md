# ecx duo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ecx duo "<goal>"` runs Claude and Codex together, autonomously, on one goal in the current repo, with a live local web screen where the user watches, talks (@mentions), approves the plan and risky actions, and gets a report plus a tamper-proof action log.

**Architecture:** One Python asyncio process. It drives Claude Code (print mode, stream-json in/out, permission prompts answered by the host) and Codex (`codex app-server`, JSON-RPC over stdio, ephemeral thread) as two `Agent` adapters. An `Orchestrator` forwards each agent's messages to the other, applies one `policy` to every permission request (allow / approval card / block), tracks phases (plan, build, done), and writes every event to an append-only log. A small threaded HTTP server streams that log to a single static page over SSE and takes the user's messages, card answers and pause/stop.

**Tech Stack:** Python 3.10+ stdlib only (asyncio, http.server, unittest), vanilla HTML/CSS/JS, Claude Code 2.1.316, codex-cli 0.165.0.

**Spec:** `docs/superpowers/specs/2026-11-10-duo-design.md`

## Global Constraints

- Stdlib only, no pip dependencies (ECX convention). Tests: `python -m unittest discover -s tests -v`.
- No roles. Nothing in the brief or code assigns lead/builder/reviewer.
- Nothing is built before plan approval; destructive or outward actions always produce a card; the danger guard's BLOCK list always blocks.
- Duo sessions never land in the user's normal history: Claude with `--no-session-persistence`, Codex threads with `ephemeral: true`. Duo keeps its own log only.
- User hooks never run inside duo: Claude gets `--settings '{"disableAllHooks": true}'`; Codex gets `-c features.codex_hooks=false` (verify key in Task 1).
- Web server binds `127.0.0.1` only and requires a per-run random token on every request.
- Defaults: Claude model `sonnet`, Codex model = its default, effort `medium`; `--best` sets Claude `opus` and Codex effort `high`. Backstop `--hours 2` and 400 total agent turns; on hit, pause and ping.
- Run folder `<workdir>/.duo/<YYYYmmdd-HHMMSS>/`, added to `.git/info/exclude`, never to a tracked file.
- Branch per run: `duo/<YYYYmmdd-HHMMSS>-<slug>` where slug is the first 5 goal words, lowercase, `[a-z0-9-]`, max 40 chars.
- The vault (`$ECX_VAULT`) is refused as a work folder in v1. Protected paths come from `ECX_PROTECTED` (colon-separated, default `~/Downloads/yep`), and any tool touching them is blocked.
- Agent-sync is read only from duo (no cursor writes). Send/inbox mail is not used.
- No em dashes in any user-facing copy.

## Review Focus

1. Dirty working tree at start: the user expects duo to refuse ("commit or stash first") rather than mix their uncommitted work into the agents' commits. Test in Task 10.
2. A Codex `apply_patch` that deletes a file that existed at start must open a card, not slip through as a "file change". Test in Task 3 (policy) and Task 6 (adapter maps delete kinds).
3. Another local web page or process POSTing to the duo server must be rejected without the token. Test in Task 9.
4. The user hits Stop while a card is waiting: the card must be resolved as denied and both agents interrupted, and the report must still be written. Test in Task 8.
5. One agent process crashes mid-run (Claude exits, app-server dies): duo must log it, show it, pause the run and ping, not hang or silently continue solo. Test in Task 8.

### Task 3: Policy (allow / card / block)

The single place that decides every permission request from either agent.

**Files:**
- Create: `duo/policy.py`
- Test: `tests/test_duo_policy.py`

**Interfaces:**
- Consumes: `hooks/guard_dangerous.py` `decide(cmd) -> (decision|None, reason|None)` (import by file path with `importlib.util`).
- Produces:
  - `@dataclass Ctx: workdir: str; phase: str  # "plan" | "build"; existed: set[str]  # abs paths present at start; created: set[str]  # abs paths created this run; protected: list[str]`
  - `@dataclass Request: agent: str; tool: str; input: dict` where `tool` is normalized: `"bash"` (input `{"command"}`), `"write"` (`{"path"}`: whole-file write), `"edit"` (`{"path"}`), `"delete"` (`{"path"}`), `"read"` (`{"path"}`), `"web"` (`{"url"}`: fetch/search), `"mcp"` (`{"name", "args"}`), or the raw tool name for anything else.
  - `classify(req: Request, ctx: Ctx) -> tuple[str, str]` returning `("allow"|"card"|"block", reason)`.

Rules, first match wins:
1. Any path or command touching a `ctx.protected` path → `block`.
2. `bash`: guard BLOCK → `block`; guard ASK → `card`; outward patterns → `card`: `\bgit\s+push\b`, `\bgh\s`, `\bcurl\b.*(-X\s*(POST|PUT|PATCH|DELETE)|--data|-d\s|-F\s|--form)`, `\bwget\b.*--post`, `\bnpm\s+publish\b`, `\bvercel\b`, `\bnetlify\b`, `\btwine\s+upload\b`, `\b(ssh|scp|rsync)\b.*@`, `\b(sendmail|mail)\b`; `\brm\b` or `\bgit\s+rm\b` whose targets include a path in `ctx.existed` (or a glob/dir) → `card`; package installs that are global (`-g`, `--global`, `brew install`, `pip install` without an active venv path in workdir) → `card`.
3. In `phase == "plan"`: `write`/`edit`/`delete` outside `<workdir>/.duo/` → `block` with reason "The plan is not approved yet. Write notes in the run folder."; `bash` not matching a read-only prefix list (`ls cat head tail wc grep rg find git status git log git diff git show pwd echo tree which python --version node --version`) → `card`.
4. `delete` of a path in `ctx.existed` → `card`; `write` to a path in `ctx.existed` and not in `ctx.created` → `card` ("replaces an existing file wholesale").
5. `write`/`edit`/`delete` outside `workdir` → `card`.
6. `mcp`: name's last segment matches `send|reply|post|publish|create|delete|update|forward|trash|upload|share|respond|merge|push|fork|comment|label|spam|draft|schedule|book|pay|transfer|submit|click|type|navigate|fill|form|computer|run|execute|write` → `card`; else `allow`.
7. Everything else → `allow`.

**Files:**

  - `async run(goal: str) -> str` returns final status `"done"|"stopped"`.
  - `say(text: str)` (thread-safe entry from the server): `@claude`/`@codex` at the start (case-insensitive, any order, both allowed) → those agents get `[<user> to you]: <rest>`; no mention → both get `[<user> to both]: <text>`. Logged as `user/message` with `to: [...]`.

- Signals: `[[READY: plan]]` / `[[READY: done]]` in an agent message sets that agent's readiness; any later message from it without the tag clears it. Both ready for plan (phase plan) → plan card with `plan.md` text (if `plan.md` is missing, tell both to write it instead). Both ready for done (phase build) → if `summary.md` missing, tell both; else finish: `report.write(...)` (Task 8 provides; stub until then), status `done`, close agents.
- Idle nudge: both idle, nothing queued, not finished → both get `[duo] You are both idle. Keep going toward the goal, or say [[READY: done]].`; after 3 consecutive nudges with no tool activity, pause (Task 8).
